# 광고살핌 인계 및 검증 기록

검증일: 2026-11-10 (Asia/Seoul)

**최신 배포본은 v0.3.0 `adsalpim-node21-multiuser.zip` (`adsalpim-node21-ready.zip`과 동일)입니다.** 아래 기록은 시간순이며 마지막 검증이 이전 상태를 갱신합니다.

## Claude Code가 완료한 범위

Claude Code 세션은 10:58 KST 모바일 화면 점검 도중 사용량 한도로 중단되었습니다. 당시 Next.js 프로젝트, 실제 Gemini Interactions API adapter, URL Context·검색·보고서 파이프라인, SSRF 방어, 한국어 UI, 원문 하이라이트, 다크 모드, 복사·인쇄, 모의 모드와 159개 테스트가 구현되어 있었습니다. README는 create-next-app 기본 문서였습니다.

현재 폴더에는 `.git`이 없으므로 커밋 이력 대신 Claude의 로컬 세션 기록과 실제 파일을 대조했습니다. Git 저장소 생성, 커밋, 외부 배포는 수행하지 않았습니다.

## 이번에 수정한 사항

1. API 본문 크기를 문자열 길이가 아닌 UTF-8 바이트로 계산합니다. 8 KiB를 넘으면 HTTP 413을 반환하고 스트림 읽기를 중단합니다. 누락되거나 거짓인 Content-Length에도 누적 바이트 제한이 적용됩니다.
2. 취소 신호를 Gemini 호출까지 전달하고 호출별 시간 제한과 결합합니다. 취소 후 JSON 재시도나 최종 성공 결과가 발생하지 않도록 검사합니다.
3. 본문을 읽기 전이나 읽는 도중 이미 취소된 요청도 분석 시작 전에 반영하고, 종료 시 abort listener를 정리합니다.
4. 현재 SDK가 시간 초과 후 내부적으로 다섯 번 전송을 시도하는 동작을 실제 SDK+모의 fetch로 재현했습니다. `maxRetries: 0`으로 제한하여 종료된 요청의 내부 재시도를 방지합니다. 구조화 응답 검증을 위한 명시적 재시도는 유지합니다.
5. 검증 본문에 같은 연도가 있다는 이유로 AI가 제안한 출처 발행일을 표시하던 처리를 제거했습니다. 현재 인용 메타데이터에는 출처별 발행일 증거가 없으므로 `publishedAt: null`을 반환합니다.
6. 사실 불일치 요약에서 출처의 권위를 자동으로 높이지 않도록 ‘공신력 있는 자료’를 ‘연결된 자료’로 바꿨습니다.
7. 설치, 키 설정, 실제·모의 실행, Vercel 배포, URL 제한, 개인정보 안내를 README에 작성했습니다.

수정 전 실패를 확인한 회귀 테스트 18개를 추가했습니다. 별도 리뷰 에이전트가 확인한 네 가지 발견도 재현 테스트 후 수정했습니다.

## 의존성 검사

`npm audit` 결과: **낮음 2건, 보통 10건, 높음·치명적 0건**입니다. 전이 의존성 경로를 포함하는 패키지 단위 집계이며 서로 독립적인 취약점 12종이라는 뜻은 아닙니다.

- `minimatch`: glob 패턴 처리의 자원 고갈 가능성. `ts-morph`, `@typescript-eslint/*` 경로에 존재.
- `deepmerge`: 병합 결과 객체의 prototype poisoning 가능성. `shadcn`, `@shadcn/registry` 경로에 존재.
- `npm audit fix`를 실행했으나 호환 범위 내 업데이트가 적용되지 않았습니다. `--force`가 제안하는 `shadcn@1.0.0`으로의 강제 변경은 수행하지 않았습니다.
- 현재 Next.js 실행 코드가 위 CLI 내부 기능을 직접 호출하는 경로는 확인하지 못했지만, 이 사실이 의존성 경고를 해결했다는 뜻은 아닙니다. 상위 패키지 수정이나 호환성 검증을 거친 별도 의존성 정리가 필요합니다.

## 아직 검증하지 않은 항목

- **실제 API 키를 사용한 Gemini 종단 간 분석**: 최초 점검 때는 키가 없었고, 이후 사용자 요청으로 로컬 `.env.local` 설정을 완료했습니다. 실제 Google 요청은 수행하지 않아 모델 접근 권한, 사용량 한도, 실제 도구 응답의 품질은 미검증입니다.
- **Vercel 실제 배포와 배포 환경의 연결 취소**: 로컬 프로덕션 서버와 HTTP 경로만 확인했습니다.
- **발행일 수집**: 현재 출처별 원문 메타데이터를 수집하지 않으므로 발행일을 생략합니다.
- **모든 페이지 지원**: 이미지 전용·로그인·유료·봇 차단·동적 페이지 분석을 보장하지 않습니다.
- **엄격한 전역 사용량 제한**: 현재 IP별 제한은 인스턴스 메모리 기반입니다.

실제 분석을 확인하려면 설정된 `.env.local`을 사용해 서버를 실행한 뒤 공개 광고 URL로 테스트하세요. 모의 모드 결과를 실제 Gemini 성공 증거로 사용하지 마세요.

## Node.js 배포 패키지 검증

사용자가 Node.js 서버 배포로 방향을 지정하여 기존 Next.js 서버 구성을 유지했습니다. Cloudflare 전용 변환은 적용하지 않았습니다.

- `artifacts/adsalpim-nodejs.zip`: 소스, 잠금 파일, 설정, 테스트, 실행·배포 안내 포함. `.env.local`, `node_modules`, `.next`, Claude 작업 이력은 제외.
- `scripts/package-node.ps1`: 허용한 파일만 묶고, 로컬에 설정된 API 키가 포함되어 있으면 생성을 중단.
- Undici의 실제 요구 버전에 맞춰 최소 Node.js 버전을 `22.19.0`으로 수정. 검증 환경은 Windows와 Node.js `24.15.0`.
- ZIP을 별도 임시 폴더에 압축 해제한 뒤 `npm ci --include=dev --no-audit --no-fund` 성공.
- 압축 해제한 소스로 `npm test`: **177개 통과**, `npm run lint`: 통과, `npm run build`: TypeScript 검사와 프로덕션 빌드 통과.

- `.env.local` 경로 HTTP 404, 키 미설정 HTTP 503, 외부 Origin HTTP 403, 8 KiB 초과 본문 HTTP 413 확인.

이번 검증에는 실제 Gemini 호출, Linux 서버 실행, 외부 호스팅 배포가 포함되지 않습니다.

## Node.js 21 서버 호환 검증

배포 주소 `http://play.wrd.kr:25860/`는 브라우저에서 `ERR_EMPTY_RESPONSE`, 직접 HTTP 요청에서 연결 종료를 반환했습니다. 도메인의 6개 IPv4 주소 모두 지정 포트의 TCP 연결 후 HTTP 응답 없이 종료되었습니다. 사용자가 제공한 Pterodactyl 로그에서는 `Cannot find module './index.js'`로 프로세스가 종료됐으며, Node.js 21.7.3에서 기존 패키지의 Node.js 22 요구 경고도 확인했습니다.

수정 사항:

- 서버 의존성을 `@google/genai 2.32.0`, `undici 7.30.2`, `cn 0.4.0`으로 고정하여 Node.js 21.7.3에서 사용할 수 있도록 변경.
- 실제로 사용하는 shadcn CSS를 원본 MIT 라이선스와 함께 `src/app/vendor/shadcn.css`로 복사. 서버에 불필요한 shadcn CLI 의존성 제거.
- `index.js` 추가: 현재 Node 실행 파일로 Next.js CLI 빌드 → 성공 시 프로덕션 실행. `PORT` → `SERVER_PORT` → `25860` 순서로 선택하고 `0.0.0.0`에서 수신. 빌드 실패 시 실행하지 않으며 종료 신호를 하위 프로세스에 전달.
- `.npmrc`가 TypeScript·Tailwind 등 빌드 의존성의 설치를 유지.
- 서버 ZIP에서는 개발용 테스트·린트 도구와 테스트 파일을 제외하고 별도 잠금 파일을 생성. 개발 작업 폴더의 최신 Vitest 5는 유지하며, 서버에 구형 테스트 도구를 설치하지 않음.
- 압축 해제한 `artifacts` 폴더가 개발 프로젝트의 TypeScript·ESLint 검사에 중복 포함되지 않도록 제외.

## 사양 증설 후 외부 서버 확인

이후 사용자가 서버 사양을 올려 TypeScript 검사 단계 정체가 해결되었다고 알려왔습니다. 서버 자원 부족이 원인이었을 가능성은 있으나 정확한 CPU·메모리 사용량은 확보하지 않았습니다. 별도로 준비 중이던 타입 검사 생략 변경은 적용하지 않고 기존 Node.js 21 배포 구성을 유지했습니다.

- `http://play.wrd.kr:25860/`, `/privacy`, `/legal`: **HTTP 200**, 각각 광고살핌의 예상 문서 제목 확인.
- 홈 HTML에서 참조한 JS·CSS 등 정적 자산 **12개 전부 HTTP 200**.
- `POST /api/analyze`: **HTTP 200**, NDJSON 단계 이벤트와 내부 주소 차단 오류 `BLOCKED_URL` 확인. API 키 미설정 오류는 발생하지 않음.
- 실제 Gemini 요청은 보내지 않았으므로 키 유효성·모델 권한과 최종 AI 보고서 생성은 아직 미검증.
- 자동 브라우저는 `ERR_HTTP_RESPONSE_CODE_FAILURE`로 페이지를 열지 못했으며 오류 페이지의 `data:` URL도 브라우저 도구 정책에서 차단되어, 이번 외부 서버의 시각적 검증은 완료하지 않음. 위 정상 결과는 직접 HTTP 요청으로 확인한 범위임.

## v0.1.1 배포 파일 정리

현재 서버 환경에 맞춰 `adsalpim-node21-ready.zip`으로 재포장했습니다.

- `DEPLOY.md`에 Node.js 21.7.3, `MAIN_FILE=index.js`, 포트 25860, `/home/container` 업로드 순서를 모았습니다.
- README·상세 안내·환경변수 예시에 운영 주소와 기존 `.env` 보존 방법을 반영했습니다.
- 방문자용 오류 문구에서 서버 파일·환경변수 편집 안내를 제거했습니다. 기존 오류 코드는 유지하며 관리자용 해결 방법은 배포 문서에 제공합니다.
- 타입 검사 생략 설정은 사용하지 않습니다. 실행 파일과 Next.js 설정은 사양 증설 후 작동한 구성 그대로입니다.
- `npm test`: **177개 통과**, 타입 검사·ESLint 통과.
- 새 ZIP을 검증 폴더에 적용한 뒤 실제 Node.js 21.7.3에서 자동 빌드·타입 검사·서버 시작 성공.
- 홈·개인정보·법적 고지 HTTP 200, 키 미설정 시 HTTP 503과 `MISSING_API_KEY` 코드 및 수정된 방문자 안내 확인.
- 실제 서버에 v0.1.1을 업로드하는 작업은 수행하지 않았으며, 실제 Gemini 보고서 생성 검증도 포함하지 않았습니다.

## v0.2.0 이미지 인식과 광고 화면 하이라이트

- 공개 HTML의 주요 영역을 스크립트 없이 렌더링하고, 최대 8장의 JPEG 화면과 본문을 Gemini에 함께 전달합니다. 모델의 화면 좌표는 프레임 ID와 범위를 검증하며, 이미지 인식 결과라는 표시와 오차 안내를 붙입니다.
- 원격 이미지·CSS·글꼴은 기존 DNS 고정/SSRF 검사를 통과한 수집기로만 제공합니다. 시간·요청 수·바이트·동시 캡처 제한이 있으며 실패 시 텍스트 분석으로 전환합니다.
- LG 이벤트 `detail-PE01036002?eventCode=bfdotexnmnaver`를 실제로 수집해 8장의 광고 화면을 확인했습니다. 긴 페이지 제한 안내도 확인했습니다.
- 실제 Gemini 호출로 쿠폰팩, 구독료 할인, 카드 할인, 무이자, 소모품 할인 등 이미지 문구를 읽었습니다. 별도 실제 브라우저 분석에서는 주장 8개, 그중 이미지 하이라이트 5개가 표시되고 검색·보고서 생성까지 완료됐습니다. 이는 인식과 기능 동작 검증이며 각 AI 판단의 사실성을 보증하는 검증은 아닙니다.
- 브라우저에서 카드 → 이미지 위치, 하이라이트 → 카드 펼침, 확대/화면 맞춤, 캡처 밖 텍스트의 원문 펼침·이동을 확인했습니다. 화면 기록은 로컬 `artifacts/visual-verification/highlight-preview.png`에 있으며 배포 ZIP에는 포함하지 않습니다.
- `npm run typecheck`, `npm run lint` 통과. 일반 테스트 187개 통과, 네트워크·실제 API를 사용하는 선택적 통합 검사 2개는 기본 실행에서 제외합니다. 이 두 통합 검사는 별도로 실행하여 성공했습니다.
- Linux x64 WSL + 공식 Node.js 21.7.3에서 번들 Chromium 143.0.7499.0의 실행과 JPEG 캡처를 확인했습니다. NSS 라이브러리를 함께 압축 해제해 추가 시스템 패키지 설치 없이 실행했습니다. CDP의 실제 렌더링 글꼴 조회로 한글 13글자가 Pretendard 글꼴을 사용함을 확인했습니다.
- 새 버전을 외부 Node.js 서버나 Cloudflare에 업로드하지 않았습니다. 정적 캡처이므로 페이지의 스크립트·로그인·펼치기·동영상과 캡처 한도를 넘는 하단 내용은 포함되지 않습니다.

### 최종 서버 ZIP 검사

- ZIP을 새 임시 폴더에 풀고 실제 Node.js 21.7.3으로 `npm ci --include=dev` 성공: 설치 패키지 151개, `npm audit` 취약점 0건.
- Windows/Linux x64에 적용되는 잠금 파일 패키지의 Node 엔진 요구 범위가 모두 21.7.3과 호환됨을 확인했습니다. 설치 대상이 아닌 ia32 전용 선택 패키지는 대상에서 제외했습니다.
- 실제 Node.js 21.7.3 `node index.js`로 프로덕션 컴파일·TypeScript 검사·서버 기동 성공. `/`, `/privacy`, `/legal` 모두 HTTP 200.
- 해당 프로덕션 API에서도 LG 화면 8장 수집 완료 이벤트를 확인했습니다. 이 격리 실행에서는 의도적으로 실제 키를 넣지 않아 이후 AI 단계가 오류로 종료됐습니다. 실제 키를 사용한 종단 간 분석 검증은 위 로컬 브라우저 검사에서 별도로 완료했습니다.

## v0.2.1 운영 서버 캡처 실패 수정

- 운영 서버와 Pages 홈에서 v0.2.0의 새 안내 문구가 모두 확인됐으나, 실제 서버 분석 결과에는 `visual: null`과 캡처 실패 안내가 포함됐습니다. 즉 배포 누락이 아니라 캡처 실패 후 텍스트 분석으로 전환된 상태였습니다.
- Pterodactyl 공식 기본 설정의 `/tmp` 100MB 제한을 격리된 Linux mount namespace로 재현했습니다. 기존 Chromium 압축 해제는 `ENOSPC`로 실패했습니다. 압축 해제된 Chromium 실행 파일은 약 182MiB입니다. 운영 서버의 원시 오류 로그는 이전 버전에서 기록하지 않았으므로 운영 환경의 정확한 오류 코드는 직접 확인하지 못했습니다.
- `.adsalpim-runtime/tmp`로 캡처 엔진과 임시 파일을 옮기고, NSS/글꼴 경로도 함께 수정했습니다. 같은 100MB tmpfs 제한 아래 실제 Node.js 21.7.3에서 Chromium 실행·JPEG 캡처·한글 Pretendard 렌더링이 성공했습니다. 새 시스템 패키지 설치는 필요하지 않았습니다.
- 시작 시 캡처 엔진을 미리 준비하고 확인하며, 실패하면 비밀값 없는 고정된 상태 코드만 콘솔에 기록합니다. 분석 결과에는 눈에 띄는 캡처 실패 안내와 접힌 텍스트 원문을 표시합니다.
- 타입 검사·린트·일반 테스트 187개 통과. 실제 네트워크/API를 사용하는 선택적 검사 2개는 기본 실행에서 제외됩니다.
- 이 수정은 새 ZIP 업로드 후 운영 서버에서 재확인해야 합니다. Cloudflare 화면 파일과 기존 `.env`를 교체할 필요는 없습니다.
- 환경 설정 근거: https://github.com/pterodactyl/documentation/blob/master/wings/1.0/configuration.md (`tmpfs_size` 기본값 100MB).

### v0.2.1 최종 패키지 확인

- 새 ZIP을 격리된 설치 폴더에 적용하고 실제 Node.js 21.7.3에서 `node index.js` 빌드·타입 검사·캡처 엔진 사전 검사·서버 시작 성공.
- 해당 프로덕션 API에서 LG 페이지의 광고 화면 8장 수집 완료 이벤트를 확인했습니다. 검증용 가짜 키를 사용한 이 실행에서는 AI 단계가 예상대로 거절됐으며, 추가 실제 AI 호출은 하지 않았습니다.
- 캡처 실행 파일을 일부러 없게 지정한 모의 개발 환경에서 실패 안내와 접힌 텍스트 원문을 브라우저로 확인했습니다. 실제 분석 성공과 구분되는 테스트용 모의 데이터 표시가 유지됩니다. 스크린샷: `artifacts/visual-verification/capture-failure-notice.png` (배포 제외).

## v0.3.0 여러 사용자 동시 분석

- 기존 v0.2.1은 캡처 중 추가 요청에 `CAPTURE_BUSY`를 발생시켜 텍스트 분석으로 전환했습니다. 이를 캡처 대기열로 바꿔 동시 요청 때문에 이미지가 빠지지 않게 했습니다.
- 프로세스당 분석 3건 실행 + 12건 대기 (기본값), 최대 2분 대기. 캡처 1건 실행 + 나머지 대기. 요청이 취소되거나 대기 시간이 지나면 대기열에서 제거하고, 처리 완료·오류 시 실행 자리를 반환합니다. 한도 초과는 재시도 가능한 `SERVER_BUSY`로 안내합니다.
- 일반 테스트 194개 통과: 순서 보장, 실행 수 제한, 취소, 중복 자리 반환 방지, 대기 시간 초과, 과부하 거절, 캡처 대기 한도를 이미지 없는 성공으로 바꾸지 않는 동작 포함. 네트워크/API를 사용하는 선택적 검사 2개는 기본 실행에서 제외합니다.
- 로컬 개발 서버에 서로 다른 URL/IP로 18건을 동시에 요청했습니다. AI는 모의 응답, Chromium 캡처는 실제 실행했습니다. 15건 모두 캡처 이미지와 자기 URL의 결과를 받았고 3건은 대기 한도 안내를 받았습니다. 전체 분석 대기 12건, 캡처 대기 8건, 텍스트 전환 0건, 예상 밖 오류 0건, 약 31.7초였습니다. 기록은 `artifacts/visual-verification/concurrent-result.json`에 저장하며 배포에는 포함하지 않습니다.
- 이 결과는 실제 Gemini 18건 동시 호출이나 원격 호스팅 성능 검증이 아닙니다. 운영 처리량은 서버 사양과 Gemini 할당량에 따라 달라집니다. 대기열은 단일 프로세스 메모리이며 서버 재시작 시 유지되지 않습니다.
